# Dify 并发空回答说明（通义千问）

> 日期：2026-08-13  
> 现象：多标签同时提问时，有的会话正常「讲话中」，有的回「待机」并提示「智能体无有效回答」  
> 结论：**不是本地 ASR/TTS 故障，而是 Dify 上游通义千问（DashScope）并发/限流导致部分请求未返回文本。**

---

## 1. 页面上看到什么

| 表现 | 含义 |
|---|---|
| 识别出「你说：……」 | ASR 成功 |
| LiveKit 已连接、已订阅音视频 | 推流正常 |
| 状态「讲话中」 | Dify 有文本 → TTS 合成 → 开播 |
| 状态「待机」+「智能体无有效回答」 | **Dify 返回了 0 字**，没有可合成的内容，链路在智能体处结束 |

---

## 2. 日志依据（同一次多路联调）

失败会话（示例 `sess_68c9…` / `sess_842f…`）：

```text
Dify stream end ... chars=0
events=workflow_started,node_started,node_finished,node_started,node_finished,workflow_finished
empty batch answer ... pcm=0 dify_chars=0 speaking=False
```

- 工作流被触发并很快结束（约 0.5s）  
- **没有任何 `message` 增量事件**  
- 业务侧 `dify_chars=0` → 提示「智能体无有效回答」→ 回待机  

成功会话（示例 `sess_04f2…`）：

```text
Dify stream end ... chars=1277
events=workflow_started,...,message,message,message,...
speaking start ... qa_to_speak_ms≈3s
```

同一智能体「聊天机器人」、同一时间段：有的有字、有的空跑。  
本地 TTS 双卡此时并未成为瓶颈（失败请求根本没进合成）。

---

## 3. 根因说明

当前 Dify 应用使用的模型是 **通义千问（阿里云百炼 / DashScope）**。

多学生 / 多浏览器标签同时提问时：

```text
学生端并发 ↑
  → Dify 同时发起多路 chat-messages
  → 通义 API 并发 / RPM / TPM 不够
  → 部分请求工作流空结束（常不推明确 error）
  → 学生端显示「智能体无有效回答」
```

这与「流式 vs 非流式」关系不大：**换成非流式仍会撞同一配额**，且会拖慢正常会话的首响（必须等整段答完才能 TTS）。

---

## 4. Dify / 通义侧应怎么做（优先）

1. **阿里云百炼 / DashScope 控制台**  
   - 查看该 API Key 的 **RPM、TPM、并发连接数**  
   - 免费/低配额度很小；课堂多路需升配或换更高配额 Key  

2. **Dify「聊天机器人」应用**  
   - 确认模型绑定的就是这把 Key  
   - 若有应用级并发限制，调高到至少 **8～16**（与本地 TTS 业务槽 `MAX_TTS_ACTIVE_JOBS=8` 同量级）  

3. **复测**  
   - 单标签连问：应稳定正常  
   - 4～8 标签同时问：空答应明显减少  

---

## 5. 和学生端本地栈的关系

| 组件 | 本次现象中的角色 |
|---|---|
| ASR（`:8100`） | 正常（识别文本已显示） |
| TTS（Qwen3 + vLLM FLASH，`:8091/:8092` + 适配层） | 正常；空答请求未进入合成 |
| 业务 API | 按设计：无文本则提示「智能体无有效回答」 |
| Dify + 通义千问 | **瓶颈**：并发下部分请求 `chars=0` |

本地语音能力（含双卡 TTS 约 8 路同时合成）已验证可用；**教室同时提问的上限，还会受通义配额约束**。

---

## 6. 不建议的做法

- **不要**仅为该问题改成 Dify 非流式（`blocking`）：首响变差，且仍受通义并发限制。  
- **不要**因此回退 TTS 或怀疑 LiveKit：失败会话的日志已证明卡在 Dify 空文本。

---

## 7. 可选的学生端保险（配额一时加不上时）

- 业务侧对 Dify 增加 **出站并发上限**（例如同时最多 4 路打通义，其余排队）  
- `chars=0` 时 **自动重试 1 次**  
- 提示文案改为更明确的「智能体繁忙 / 未返回文本」  

需要落地这些改动时，在业务 API 中实现即可。
